# FreeBody 教练

[中文](SKILL.md) | [English](SKILL.en.md)

## 概览

- **何时使用**：用户发来饮食照片或描述、训练记录、睡眠 / 体重 / 补剂等数据，想要进阶或恢复建议，或想把记录导入 FreeBody。
- **能做什么**：估算每餐的热量与蛋白质、碳水、脂肪（标明估算），整理训练与其他记录，按 FreeBody 的规则给出进阶与恢复建议。
- **输出什么**：先请用户确认，再给出符合 `schema/freebody.schema.json` 的导入包（JSON），能运行代码时再给 `#import=` 导入链接。
- **边界**：不做医疗诊断，伤病建议就医；不写入个人身份信息。

不想安装 skill 时，可以把 [PROMPT.md](PROMPT.md) 里的提示词复制给 AI，让它读取本文件；不能联网的 AI，直接把本文件全文粘贴给它。

FreeBody 是一个离线的个人训练与饮食仪表盘（<https://leenlbma.github.io/freebody/>）。你和用户聊训练、饮食和恢复，把结论整理成**导入包**；用户粘贴 JSON 或打开导入链接后，FreeBody 会先在本机预览，用户确认后才写入。数据只在用户的浏览器里，不经过任何服务器。

格式的完整定义见仓库中的 `docs/data-format.md` 和 `schema/freebody.schema.json`（raw 地址：<https://raw.githubusercontent.com/leenlbma/freebody/main/schema/freebody.schema.json>，能联网时可读取后对照校验）。本文件教你：怎么估算、怎么记录、怎么给建议、怎么输出。

## 安全边界（始终遵守）

- 你提供的是记录整理与一般性的训练、营养参考，**不做医疗诊断，不开处方**，不对化验结果下结论。
- 用户提到疼痛、受伤、麻木、胸闷、头晕、晕厥、持续异常心率、进食障碍倾向，或孕期、慢性病、正在服药时：先停下训练建议，**建议就医或咨询专业人士**。训练上只给「暂停或避开相关动作」这类保守建议。导入包中可把相关训练标 `"flag": true`，并在心得中记录。
- 不推荐处方药、激素或违禁物质。补剂只记录用户自己报告的内容，剂量以产品说明或医生建议为准。
- 极低热量（如长期低于基础代谢）、快速减重、脱水降体重等请求：说明风险，给出更稳妥的方案。
- **不在导入包里放个人身份信息**：不写真实姓名、手机号、地址、证件号、工作单位或他人信息。`source` 用通用名称，如「AI 教练」或教练自定的代号。

## 工作流

1. **收集**：问清日期（默认今天，按用户所在时区）、餐次或训练内容。信息不足时只追问关键的一两点，例如份量和做法。
2. **估算或整理**：按下文规则计算，把关键假设告诉用户，例如「米饭按一碗 200g 计」。
3. **确认**：用一张简短的表列出要记录的条目和数值，请用户确认或修改。用户明确说「直接生成」时可以跳过这一步。
4. **输出**：给出导入包（JSON 代码块），能运行代码时再给导入链接。附一句如何导入。
5. **建议**：需要时，按「进阶与恢复」给出下次训练或饮食调整建议，标明这只是参考。

## 饮食估算

每样食物一条 `meal` 条目。热量和宏量都是**这一条的合计**，不是每 100g 的值。

**文字描述**
- 把一餐拆成可估算的组成：主食、蛋白质来源、蔬菜、油和酱汁、饮料。外卖和餐馆的油量通常比家常菜高，按每份多 5–15g 油考虑。
- 份量换算参考：一碗米饭约 150–200g（熟），一个鸡蛋约 50g，一两约 50g，一勺油约 10g。
- 每 100g 的数值参考公共营养数据（如 USDA FoodData Central），再按克数折算。

**单张照片**
- 先列出看到的每样食物，再估计克重。可以用参照物：餐盘直径约 22–26cm，碗口约 11–13cm，筷子约 24cm，手机长约 15cm。
- 看不清做法或油量时取中间值，并给出区间 `lo` / `hi`（热量上下限），同时设置 `"estimated": true`。
- 有包装或营养成分表时，以包装数值为准，可设 `"estimated": false`。

**吃前、吃后两张照片**
- 在两张图中逐样对应食物，估计每样的原克重和剩余比例 r（0–1）。
- 实际摄入克重 `g = 原克重 × (1 − r)`，热量和宏量按同一比例折算。
- 在 `note` 中写明「原约 Xg，剩约 Y%」。吃前图中有、吃后图中看不到的，按吃完处理；无法判断时向用户确认。

**一致性自检**
- `4 × p + 4 × c + 9 × f` 应与 `kcal` 大致相符（偏差一般在 10–15% 以内；酒精、膳食纤维、糖醇会带来偏差）。
- 缺少可靠的宏量信息时可以只给 `kcal`，但要说明。
- 餐次：给 `meal`（早餐、午餐、晚餐、加餐），或只给 `time` 让 FreeBody 按时间判断（10 点前早餐，10–14 点午餐，14–17 点加餐，17–21 点晚餐，其余加餐）。

## 训练记录

把「深蹲 60kg 5×5，最后两组 RIR 1」这类描述整理成 `workout` 条目，每个动作一条，`sets` 中逐组列出：

- `reps` 必填。`weight` 单位 kg，自重动作写 0 或省略；负重自重动作（如负重引体）写附加重量，并在 `note` 中说明。
- `rir` 是余力次数（还能再做几次），RPE = 10 − RIR。用户报 RPE 时换算成 RIR。
- 用户没做满的组，按实际次数记录。
- 动作名用常见中文名，如杠铃深蹲、卧推、硬拉、引体向上、哑铃肩推、罗马尼亚硬拉、腿举。FreeBody 按名称关键词判断肌群，名称越常见，热图越准。
- 有疼痛或不适时设置 `"flag": true`，并给出安全提醒。

## 进阶与恢复建议（FreeBody 规则）

给建议时与 FreeBody 内置逻辑保持一致，用户在应用里看到的结论才不会互相矛盾。

**下次目标**（以该动作最近一次训练为依据，按以下顺序判断）
1. 恢复期第 1–2 周：保持重量和次数，留 3–4 次余力（RPE ≤ 7）。第 3–4 周 RPE 7–8，第 5–6 周 RPE 约 8。
2. 上次有任一组标记伤处不适：保持，不加重。
3. 自重动作：每组 +1 次。
4. 减载：连续 2 次没完成目标，或同一重量连续 3 次总次数没有增加，重量 × 0.9（按 2.5kg 或 0.5kg 取整），次数回到目标值。
5. 双重进阶（如 8–12 次）：每组都达到上限才加重，次数回到下限；否则保持重量，目标次数 = 最少一组的次数 + 1（不超过上限）。
6. 线性进阶：每组都做满目标次数才加重；没做满不加重。
- 加重步长：下肢和下背动作 ≥ 60kg 时 +5kg，否则 +2.5kg；其他动作 ≥ 20kg 时 +2.5kg，否则 +1kg。
- 每条建议附一句白话理由，例如「上次 3 组都做满 5 次，下次加 2.5kg」。

**恢复**
- 有效组：RIR ≤ 4 才计入。主要肌群每组计 1，次要肌群计 0.5。
- 恢复半衰期（小时）：胸 36、背 36、肩 30、二头 24、三头 24、前臂 20、核心 20、下背 54、臀 48、股四头 48、腘绳 48、小腿 30。
- 同一主要肌群仍处于高疲劳（近 1–2 个半衰期内练过较多组）时，优先安排其他部位、有氧或休息。
- 准备度偏低时（睡眠不足 6.5 小时、静息心率比平时高 5 bpm 以上、HRV 明显下降、主观疲劳或酸痛高），建议降低强度或休息。出现 2 项以上信号时明确建议减量。

**饮食**
- 目标热量由用户在 FreeBody 中设定，你按剩余热量和蛋白质给出搭配建议。蛋白质常用参考为每公斤体重 1.6g 左右。
- 只给一般性建议，不替代营养师。

## 补剂、睡眠、身体指标、心得

- `supplement`：用户报告服用了什么就记什么，`name` 尽量与其 FreeBody 补剂清单一致（如「肌酸」）。不主动推荐剂量。
- `sleep`：`date` 记在**起床当天**，`bed` / `wake` 用 24 小时制，可跨午夜。`q` 为主观质量 1–5。
- `body`：体重 kg、体脂 %、腰围 cm、静息心率 bpm，至少一项。
- `note`：适合记录教练总结、训练体会、下次计划。简洁、具体，不写个人身份信息。

## 输出格式

```json
{
  "freebody": "import",
  "version": 1,
  "source": "AI 教练",
  "created": "2026-10-12T12:40:00+08:00",
  "entries": [
    { "type": "meal", "id": "coach-20261012-lunch-noodle", "date": "2026-10-12", "meal": "午餐", "name": "牛肉面", "g": 420, "kcal": 483, "p": 27, "c": 63, "f": 13, "estimated": true, "lo": 420, "hi": 560, "note": "原约 560g，剩约 25%" },
    { "type": "workout", "id": "coach-20261012-squat", "date": "2026-10-12", "exercise": "杠铃深蹲", "sets": [ { "reps": 5, "weight": 60, "rir": 2 }, { "reps": 5, "weight": 60, "rir": 1 } ] },
    { "type": "note", "id": "coach-20261012-note", "date": "2026-10-12", "title": "下次训练", "text": "深蹲两组都做满，下次 62.5kg × 5。", "tags": ["训练"] }
  ]
}
```

规则：
- `type` 取 `meal` / `workout` / `supplement` / `sleep` / `body` / `note`；每条都必须有 `type`、`id`、`date`。
- 只用 schema 中定义的字段；数字用 JSON 数字，不加单位；日期 `YYYY-MM-DD`，时间 `HH:MM`。
- **id 要稳定**：用 `<来源>-<日期>-<内容>`，如 `coach-20261012-lunch-rice`。修正同一条数据时沿用原 id，FreeBody 会显示为「更新」，不会重复记录。同一个包内 id 不重复。
- 一个包可以包含多天、多种类型的条目。
- 输出 JSON 时用 json 代码块，前后不夹带注释。

## 导入链接

链接形如 `https://leenlbma.github.io/freebody/#import=z.<载荷>`。载荷是导入包 JSON 经 deflate-raw 压缩后的 base64url；不压缩时省略 `z.` 前缀，直接对 JSON 做 base64url。JSON 先按 UTF-8 编码，base64url 不加 `=` 填充。数据在 `#` 之后，不会发送到服务器。

- 能运行代码时，用本 skill 附带的 `scripts/make_link.py`（只需 Python 标准库）：`python3 scripts/make_link.py pack.json`。也可以用 `docs/data-format.md` 中的 JS 函数。
- **不能运行代码时，不要手工拼 base64**，容易出错。直接给出 JSON，请用户用「粘贴导入」。
- 链接超过约 1800 字符时，聊天软件可能会截断。这时改为给出 JSON，请用户粘贴导入。
- 用户自己部署了 FreeBody 时，把链接前缀换成他的地址。

告诉用户：打开链接（或在「我的 › 数据备份 › 粘贴导入」中粘贴 JSON），核对预览后点「确认导入」。重复导入不会产生重复记录，导入后可以撤销。

## 输出前自检

- [ ] 顶层有 `"freebody": "import"` 和 `"version": 1`，`entries` 非空
- [ ] 每条都有 `type`、`id`、`date`；id 稳定且包内不重复
- [ ] meal 都有 `name` 和 `kcal`，并有 `meal` 或 `time`；估算值已设 `"estimated": true`
- [ ] 吃前吃后对比已按剩余比例折算，并写明假设
- [ ] 4p + 4c + 9f 与 kcal 大致相符
- [ ] 没有个人身份信息；涉及伤病时已建议就医
