# Extending the food library

[中文](food-database.md) | [English](food-database.en.md)

The food library lives in `data/foods.json` and is inlined into `index.html` at build time. Users can also extend it on their own device under 我的 › 食物库 › 导入自定义食物 JSON (Me › Food library › Import custom foods JSON). That copy stays in the browser and never touches the repository.

## Format

```json
{
  "version": 4,
  "per": "100g",
  "note": "description",
  "foods": [
    { "id": "rice-cooked", "name": "米饭（熟）", "category": "主食", "kcal": 116, "p": 2.6, "c": 25.9, "f": 0.3,
      "fib": 0.4, "na": 1, "aliases": ["饭", "白饭"],
      "servings": [{ "unit": "碗", "g": 200, "label": "1碗米饭≈200g" }],
      "source": "自整理（参考 USDA FoodData Central，CC0）",
      "ref": "参考 USDA FoodData Central 同类条目（v2.1 自整理近似值）" }
  ]
}
```

Names, categories, units and labels are in Chinese because they appear in the interface.

| Field | Required | Meaning |
|---|---|---|
| `id` | yes | A unique kebab-case English id, e.g. `chicken-breast-cooked` |
| `name` | yes | Chinese name. State whether the food is raw or cooked, and any other key detail. |
| `category` | no | One of 主食 (staples), 蛋白质 (protein), 乳制品 (dairy), 蔬果 (fruit and veg), 油脂坚果 (fats and nuts), 零食饮料 (snacks and drinks), 调味品 (condiments), 菜肴 (dishes), 汤粥 (soups and congee) |
| `kcal` `p` `c` `f` | yes | Energy (kcal), protein, carbohydrate and fat (g) **per 100 g of edible portion**. Non-negative numbers. |
| `aliases` | no | Alternative names used to match quick text entry, e.g. `["鸡蛋","蛋"]` |
| `fib` `na` | no | Fibre (g) and sodium (mg) per 100 g. Leave them out if you have no reliable value. |
| `servings` | no | Common portions, e.g. `[{"unit": "碗", "g": 200, "label": "1碗米饭≈200g"}]`. Quick entry such as `米饭1碗` then counts 200 g. The older `units: {"碗": 200}` form still works. |
| `source` | yes | Type of source. Only redistributable sources are accepted: values compiled by this project, or USDA FoodData Central (public domain / CC0). |
| `ref` | yes | The specific reference. For an ingredient, give the USDA FDC description you used, e.g. `USDA FDC: Rice, white, long-grain, regular, raw, unenriched`, so it can be checked on fdc.nal.usda.gov. For a cooked dish, give the recipe and yield, e.g. `自拟配方（生重）：番茄 200g、鸡蛋 100g…；熟重按生重 85% 计` (own recipe, raw weights: tomato 200 g, egg 100 g…; cooked weight taken as 85 % of raw). |

### How the data is produced (since v2.4)

`data/foods.json` is generated by `scripts/gen-foods.js` (`node scripts/gen-foods.js`) and holds about 320 entries.

- **Ingredients** (grains, meat, eggs, fruit and vegetables, soy products, condiments and so on): approximate values per 100 g of edible portion, compiled item by item from public USDA FoodData Central entries (public domain / CC0) and rounded. `ref` names the entry used. For ingredients specific to Chinese cooking, such as gai lan or amaranth greens, the closest USDA entry is used and `ref` marks it as an approximation (「近似」).
- **Cooked dishes, dumplings and buns, soups and congee:** each is built from a home-style recipe written for this project, with raw weights. The ingredient values are summed and converted to per-100 g values with a cooked-weight yield that accounts for water lost in cooking. Recipes, names, ids and categories are all original to this project.
- **No wholesale copying:** no third-party food composition table or dataset is copied wholesale. That includes the China Food Composition Tables and the data of other open-source apps. No online database is scraped in bulk.
- **Older entries:** entries from v2.1–v2.3 keep their original ids and values and only gain a `ref`, so existing logs are unaffected.
- **Estimates only:** every value is an estimate for reference. Packaging labels take precedence, and nothing here is nutritional or medical advice.

### How quick entry matches foods

1. **Splitting:** input is split into items on spaces, commas, the Chinese enumeration comma, semicolons and plus signs. Number words such as 一 / 两 / 半 before a unit become digits.
2. **Parsing:** each item is parsed into name + quantity + unit. The quantity may come first or last, as in `200g鸡胸肉` or `鸡胸肉200g`.
3. **Matching order:**
   1. custom foods and combinations, matched on the whole name (names may contain `+`);
   2. "常用食物" (favourites), counted per serving;
   3. the library, by name and alias: an exact match wins over the longest contained keyword.

   Energy-only entries are recognised in two forms. `外卖 650` (takeaway 650) counts when no food matches, the number is at least 50 and has no unit. `奶茶 400kcal` / `400大卡` (bubble tea 400 kcal) counts when the unit is explicit. Both are logged as 「仅热量」 (energy only).
4. **Units:**
   - `g / 克 / ml / 毫升 / kg` are treated as weight;
   - count units are looked up in `servings`;
   - with no unit, a number of 10 or more is read as grams, and a smaller one as a count of the first serving unit;
   - with no quantity at all, one serving unit or 100 g is assumed.

In-app imports also accept a bare array `[ {...}, ... ]`. Invalid entries are skipped, and an entry with the same name replaces an existing custom food.

## How to contribute

1. **Where to add entries:** add ingredients or dishes to the `BASE` / `RECIPES` lists in `scripts/gen-foods.js` and run `node scripts/gen-foods.js`. Alternatively, append entries to the end of `data/foods.json`; the generator keeps entries it does not manage. Keep raw and cooked versions of a food separate.
2. **Sources:** put the source type in `source` and the specific entry or recipe in `ref`. Only values compiled by this project or taken from USDA FoodData Central (CC0) are accepted. Do not enter values from copyrighted databases, including other open-source apps' food data.
3. **Checks:** run `node scripts/build.js` and `node scripts/check.js`. They verify:
   - required fields and numeric types;
   - unique ids and names;
   - a present `ref`;
   - rough consistency between energy and macros.
4. **Self-check:** `4p + 4c + 9f` should be close to `kcal`. Fibre and alcohol account for some deviation.

## Notes

- **Brand-sensitive foods:** all values are approximate. For foods that vary a lot by brand, such as protein powder and snacks, add 「因品牌差异大」 ("varies widely by brand") to the name.
- **No personal entries:** do not submit anything that identifies a person, such as "So-and-so's breakfast".
