# Contributing

[中文](CONTRIBUTING.md) | [English](CONTRIBUTING.en.md)

Thanks for helping out. FreeBody sticks to three principles: **no runtime dependencies, a single file, and full offline use**. The development tools (ESLint, Prettier, TypeScript type checking, Playwright) are devDependencies only and never end up in `index.html`.

## Workflow

1. Fork and clone the repository.
2. Edit files under `src/`, `data/` or `examples/`. **Do not edit the root `index.html` directly**; it is generated by the build.
3. Install the dev tools and run the checks:
   ```bash
   npm ci                 # install the pinned devDependencies
   npm run build          # write index.html and sw.js
   npm run check          # syntax, emoji, food library, import-pack schema
   npm run lint           # ESLint + Prettier check (npm run format fixes formatting)
   npm run typecheck      # tsc --checkJs over src/ using JSDoc and types/*.d.ts
   npm test               # unit tests (npm run test:coverage for coverage)
   npx playwright install chromium webkit   # once, before the end-to-end tests
   npm run test:e2e       # every page loads without errors, axe 0 violations, import, demo mode, corrupt data
   ```
   `npm run verify` runs build, check, lint, typecheck and the unit tests in one go. CI also checks that the committed `index.html` matches a fresh build and that the logic modules keep at least 85% line coverage.
4. Open `index.html` at phone width (390 px, for example) and check it in both the light and dark themes.
5. If you have a real device, run the relevant parts of [docs/device-test.en.md](docs/device-test.en.md) and note the device and results in the pull request.
6. Open a pull request with a short entry under "未发布" (Unreleased) in `CHANGELOG.md`. Include both the source changes and the rebuilt `index.html`.

## Code conventions

- **Language level:** plain JavaScript, ES5 style, so older mobile browsers keep working. No frameworks, no CDNs, no network requests.
- **Module layout:** application logic lives in `src/app/`. The build concatenates the files in file-name order into one IIFE (a shared scope, no module loader). `00-core` (state and constants), `01-store` (storage, quota warnings, backup reminders), `02-util`, `03-calc` (core calculations), `04-import` (import parsing and merge), `05-demo` (demo data) and `06-crypto` (encrypted backups) only define things, never touch the DOM, and are covered by the unit tests in `tests/`. `09-init` reads the stored data. Files from `10-ui-*` onwards are page UI, and `90-boot` is startup. Modules must not overwrite each other's functions: code that has to run after a render, a page switch or a theme change registers with `HOOKS.render / show / theme.push(fn)`.
- **Types:** data structures are declared in `types/model.d.ts`, globals and DOM additions in `types/globals.d.ts`. Add JSDoc (`/** @type {...} */`) for new constant tables or complex structures so that `npm run typecheck` stays at zero errors. Name new files `NN-name.js` with a one-line description at the top, and add tests when you change calculation or import logic.
- **Adding a section:** each module is split into commented sections (`/* ---------- section ---------- */`). Follow the same steps for a new one:
  1. add its defaults to `defaults()`;
  2. write a `rXxx()` render function;
  3. register it in `render()`;
  4. add it to `GROUPS` / `SEC_LABEL` for navigation.

  Hub pages listed in `HUB` show no sub-tabs; detail pages get a back button automatically.
- **Keep the UI lean:**
  - no more than four bottom tabs;
  - new features go into existing cards or a "更多" (More) fold first;
  - forms show only the required fields by default, with everything else inside `<details class="more">`;
  - copy should fit in one sentence where possible.
- **New data fields:** give each a default in `defaults()`, so older data is filled in on load, and update `docs/data-model.md`.
- **Escaping:** pass user input through `esc()` before rendering it as HTML.
- **Accessibility:**
  - icon-only buttons need an `aria-label`;
  - tie each `<label>` to its input with `for` (`a11y()` in `90-boot.js` fills this in for an adjacent control, but write it in the source where you can);
  - clickable cards use `data-go` / `data-sub` and get focus and button semantics automatically;
  - `charts.js` generates a text summary and a data table for every chart, so put an `<h3>` above each chart as its name;
  - animation must stop under reduced motion (the global styles already cover CSS animations and transitions).

  Check with a tool such as axe before submitting; the target is zero violations.
- **Demo data** lives in `05-demo.js` and must stay fictional. When you add a data type, add a few demo records for it.
- **No emoji in the interface.** Add icons to `src/icons.js` in the house style: 24×24, 1.5 px stroke, no fill, round caps, `currentColor`. Use `<i data-ic="name"></i>` in HTML and `IC('name')` in JavaScript.
- **Charts:** use `src/charts.js` (`FitCharts.line / bars / stack / donut / hbars / heat`). Use CSS variables for colours only, and always provide empty-state copy.
- **Muscle mapping:** exercise-to-muscle keywords live in `EX_MUS`, with the most specific keywords first. Muscles and their recovery half-lives live in `MUS`. If you change either, update `docs/data-model.md`.
- **Other projects' work:** never copy code, copy or assets from other projects, especially GPL/AGPL ones. Borrowing an interaction idea is fine if you implement it yourself and mention it in NOTICE. Any third-party data under MIT or a similarly permissive licence must keep its copyright notice in NOTICE and the README.
- **Health wording:** health-related copy stays within "logging and reference". No diagnoses and nothing that reads like a prescription.

## Import format and skill

- **Three definitions:** the import-pack format is defined jointly by `docs/data-format.md`, `schema/freebody.schema.json` and the app's `impRow()`, and all three must agree.
- **Adding a field:** update the schema, the samples in `examples/import/`, both language versions of the docs, and `skills/freebody-coach/` together.
- **Validation:** `npm run check` validates the samples and the JSON examples in the docs against the schema.
- **The skill** must contain no personal information and must keep its safety boundaries: no medical diagnosis, and injuries are referred to a professional.

## Documentation languages

The interface is Simplified Chinese only; the documentation is bilingual. When you change the README, `docs/data-format`, `docs/food-database`, this file or the skill, update the matching `.en.md` as well. The English version may be phrased freely, but it must cover the same content.

## Food library contributions

See [docs/food-database.en.md](docs/food-database.en.md). Always name the data source. Values are per 100 g of edible portion.

## Privacy red lines

- Never commit real personal records, such as exported JSON or screenshots containing real data.
- `examples/` may hold **configuration and lists** only. No records such as body weights, lab values or performances. Sample import packs in `examples/import/` must be clearly generic.

## Code of conduct

Be kind, be respectful, and keep discussion about the work.
